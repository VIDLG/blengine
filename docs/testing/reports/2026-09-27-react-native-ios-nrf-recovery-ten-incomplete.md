# React Native iPhone nRF52840 ten-cycle RF attempt: incomplete gate

Date: 2026-09-27. Scope: private RN/Nitro iPhone host and standalone nRF52840. This is **not a ten-cycle RF gate pass**.

The signed iPhone host built and launched. The ignored attempt log at `tests/consumers/react-native-internal/ios/build/device-rf-recovery-ten.attempt.log` records, on one RN probe and listener, ten ordered cycles (0 through 9) of scan, connection, GATT discovery, Notification enable and exact `ef` value, fixture-triggered passive disconnect, old-route silence, new-ID recovery connect, and requested recovery disconnect. It also records `rf-recovery-ten:close:passed:listener-removed=true:probe-closed=true`. The UI displayed ten cycles passed. The final JS `rf-recovery-ten:passed:cycles=10` line did not appear in the device console; the original controller waited for it for several minutes before the user stopped the command. The terminal interruption bypassed process-local cleanup; the specific detached `devicectl` and fixture processes were inspected and stopped, and the stale RN lock was removed after confirming the parent runner was gone.

The root cause was an incorrect console completion authority: `tools/react_native/run_ios_device_runtime.py` required an optional final JS summary after the already observed native-close marker. The same script already used a bounded post-close grace for some other modes, but did not recognize recovery close. The corrected controller now ends on the `rf-recovery[-ten]:close:passed:` marker and fails within 15 seconds if close does not follow the final cycle. `tools/react_native/check_runtime_log.py` still requires every ordered cycle, exact IDs/service/peripheral correlations, and successful listener removal/probe close; an optional final JS summary is accepted only in its correct position. A missing or failed close never counts as passed. Tests cover close without the optional summary, missing close, missing/foreign/out-of-order cycle evidence, bounded child process termination, and no-terminal failure.

After the change, the independent checker accepts the historical interrupted attempt log, but **the original recipe did not exit successfully** and cleanup required manual intervention. That post-hoc check must not be relabeled as a passed end-to-end gate. A new full `pixi run just react-native host-ios-device-rf-recovery-ten <udid> <team>` run with checker and automatic fixture cleanup remains required to claim a ten-cycle pass. The preexisting three-cycle RF gate remains separate.

The UI flow is already suitable for signed iPhone XCUITest assertions. The external BTP nRF fixture, host ACKs, and production UniFFI event-ledger validation cannot be replaced simply by choosing a React Native UI-testing framework. The `devicectl --console` controller is a transport, not the test oracle.
